# Frozen API contract v1.0.0

Source schemas: src/lib/contracts/index.ts (Zod, usable by frontend; no server dependencies). Full response examples: docs/api-examples.json, generated by npm run contracts:examples from actual fixture route handlers and validated before serialization. Changes require Codex/Antigravity coordination and version bump for breaking changes. Do not infer missing endpoints from UI placeholders.

All JSON success responses are `{data,meta}`. Common meta is required, not optional: contractVersion, mode (fixture|database), batchId, dataSourceStatus, analysisStatus, provenance (source, label, methodologyVersion), limitations[]. All errors are `{error:{code,message}}`, never traces or raw DB messages. Errors have no success meta. Common HTTP codes: 400 invalid inputs, 401 writes require authentication, 403 unauthorized scope (reserved), 404 unknown batch/issue, 413 file limit (reserved import), 415 unsupported file (reserved import), 503 database not configured, 500 unexpected server failure. Errors use no-store; success JSON uses no-store.

Phase 1 examples use authored fixture data. Phase 2 implements the same GET contracts over the official generated read-only artifact and private authenticated Supabase batches. POST/PATCH are active only with configured cookie authentication, applied RPC migrations, enabled writes and (in production) APP_ORIGIN; otherwise they return 401. All schemas remain v1.0.0 unchanged. See docs/SUPABASE_SETUP.md and docs/OFFICIAL_DATA.md for activation/deployment limits.

| Endpoint | Request schema / response schema | Behavior |
| --- | --- | --- |
| GET /api/dashboard | BatchQuery / DashboardResponse | summary, topIssues[] |
| GET /api/feedback | FeedbackQuery / FeedbackResponse | data.view and discriminated items[], paginated meta |
| POST /api/feedback/import | ImportFileMetadata plus multipart file / ImportResponse | Reserved atomic CSV import |
| POST /api/feedback | ManualFeedbackRequest / ManualFeedbackResponse | Reserved owner-scoped record |
| GET /api/issues | IssuesQuery / IssuesResponse | data.items[], optional status filter |
| GET /api/issues/:id | Id + BatchQuery / IssueDetailResponse | issue, evidence[], recommendations[], actions[] |
| PATCH /api/issues/:id | Id + IssuePatchRequest / IssuePatchResponse | Reserved status/notes update |
| POST /api/issues/:id/actions | Id + ActionRequest / ActionResponse | Reserved tracking action |
| GET /api/decisions | DecisionsQuery / DecisionsResponse | objective, rankedIssues[], methodologyVersion |
| GET /api/data-lab | BatchQuery / DataLabResponse | summary, imports[], adaption, top20RecordCount, officialDatasetAssertions |
| GET /api/reports/export | ExportQuery / ExportRow (per row) | text/csv attachment; deliberate success-envelope exception |

Query parameters are strict: unknown or duplicate keys return 400. All read endpoints accept optional batchId (default fixture-batch-v1); a missing batch returns 404. Feedback: q max 200 chars, category one exact supplied category, sentiment positive|negative|neutral|mixed|unknown, view records|patterns (default records), page positive integer ≤1,000,000 (default 1), pageSize integer 1–100 (default 20). Search uses the same whitespace/case fold as grouping, substring matching. Pattern category filter matches any category with positive membership; occurrenceCount always reflects the whole pattern. meta.total/totalPages are after filtering; out-of-range pages return empty items with unchanged totals; zero matches means totalPages=0. Ordering is original row/first-seen pattern order, deterministic.

Issues status: open|investigating|planned|resolved. Decisions objective: safety|experience|operations (default safety). Export format: csv only (default csv). Dynamic issue id is a bounded string; SQL adapter IDs can be UUIDs later without changing the contract.

Multipart import (Phase 2): one field `file`, UTF-8 .csv with exact `review,category` header; no client owner_id or official-source override. Maximum 5 MiB file and bounded multipart overhead must be enforced before decoding; allowed MIME text/csv, application/csv, application/vnd.ms-excel, application/octet-stream, or empty. Max 50,000 source rows and 10,000 review chars; recoverable semantic row failures have rowNumber/reason; broken quoting/encoding/header or zero accepted rows fail the import. Return recordCount, uniqueTextCount, repeatedRecordCount, rejectedCount, rejectedRows[], batchId, idempotentReplay. Scope+content hash retries return same batch and true; service should not count rows twice. Raw data remains retained. Future writes must be authenticated and scoped server-side before body reads. Import metadata size describes file bytes; deployment must separately cap streamed request bytes.

Manual JSON: `{review,category,observedAt?}` with review trimmed 1–10000 chars; observedAt ISO datetime or null (default null). PATCH JSON: `{status?,notes?}` at least one property, notes max 4000 chars. Action JSON: `{description,notes?}` description trimmed 1–2000 chars, notes max 4000 default empty. Unknown JSON keys rejected. Success manual returns a record, patch an issue, action an action with server IDs/times; never indicate synchronous Adaption execution.

Records carry kind=record, id, batchId, rowNumber, rawText, category, normalizedHash, source, importedAt, observedAt=null, annotation or null. Patterns carry kind=pattern, batchId, normalizedHash, normalizedText, exampleOriginalText, occurrenceCount, categoryCounts, annotation or null. Each annotation carries sentiment, severity, issueTypes, aspects (topic/sentiment/evidenceQuote), explanation, evidenceQuote, analyzedBy, pipelineVersion, reviewStatus and nullable confidence. Rule-based mixed reviews retain both aspects. Only supported negative aspects yield issue evidence; denied fraud assertions do not support fraud issues. Heuristic confidence is null.

Summary denominators are explicit: raw categoryCounts; categoryPatternCounts per distinct category/text pair; sentimentCounts over patterns including unknown; annotationCoverage over patterns with non-unknown sentiment; timestampCoverage over raw records with real event date. Coverage is `{covered,total,ratio,basis}`, ratio null for empty total. uniqueCustomers and timeTrends are `{status:"unavailable",value:null,reason}`. Counts and coverage are not model accuracy.

Priority factors/weights are severity, distinctPatternShare, negativeShare (negative or mixed supporting patterns), evidenceCoverage. Scores are deterministic 0–100 with methodologyVersion and rationale. No raw repetition factor, fabricated impact, customer count, dollar estimate or prediction confidence. Evidence contains role, pattern and bounded raw samples; template recommendations identify source=template. Issue timestamps refer to issue creation, not customer complaints.

Adaption Data Lab defaults to status=not_configured, runs=[] and evaluation unavailable. It does not claim imported samples are optimized training data. Source/analysis statuses support not_configured|pending|processing|partial|ready|failed; fixture source is ready and heuristic analysis is partial. officialDatasetAssertions=pending while no genuine file is validated. Future adapters must preserve unavailable states rather than zero-fill them.

CSV export columns: metric,value,basis,source,limitation. No JSON success envelope; Content-Type=text/csv, fixed Content-Disposition filename, all cells quoted, double quotes escaped, formula prefixes neutralized. Rows expose real summary counts and honest source labels. JSON error response remains standard.

Antigravity: import schemas/types from @/lib/contracts, treat mode/provenance/limitations as visible UX, use observedAt only for complaint dates, and handle non-2xx error envelopes. Official artifact uses mode=database/source=official_csv with an explicit generated-artifact label; private persistence uses mode=database/source=manual|upload. Use batchId returned by a write to select its private snapshot on GET requests; a private UUID issue detail can infer its batch. Default reads remain the public demo. Writes require a configured same-origin sign-in flow and can still return 401. CSV retries return the existing batch; manual submissions are explicitly separate batches. Heuristic version is now v2 to preserve mixed official samples; response field shapes are unchanged. Dependency additions are server Supabase SDKs; no UI-owned source was edited.
