# Official-data delivery and production packaging

Phase 7 uses an authorized synthetic fixture preview, documented in [PHASE7_PREVIEW.md](PHASE7_PREVIEW.md). The current `.vercelignore` strictly excludes all `data/` and `artifacts/` inputs. The official dataset remains local; its future delivery requires permission and a separately reviewed upload manifest.

Future official-data method: an explicitly authorized **CLI source deployment from this prepared checkout**, with the verified processed artifact included as a private server build input after reviewing the exclusions. Raw CSV, pilot data, credentials and worktrees remain excluded. No dataset was committed, fetched remotely or uploaded in Phase 4. Vercel's Next.js adapter builds its own functions; `.next/standalone` is a local/container package, not Vercel Build Output API format. Do not send it to `vercel deploy --prebuilt`.

| Approach | Assessment |
| --- | --- |
| Generate at build time from raw CSV | Works only if approved original bytes are supplied privately to that build. Git alone supplies neither ignored CSV nor JSON. Avoid transmitting raw when generated JSON is sufficient. |
| Include verified generated JSON with CLI source | Future authorized path only. Current `.vercelignore` excludes it; a permission-reviewed exception is required. In explicit official mode, Next API traces include the artifact as server input, never a `public/` asset. |
| Authorized hosted artifact retrieval | Useful for later Git CI, but requires a chosen storage service, distribution approval, authenticated bounded download, SHA verification, failure-closed build and secret rotation. No host/URL/token/downloader is invented or configured. |
| Commit dataset/artifact | Requires explicit permission; not implemented or recommended by default. |

Publishing this app exposes original review text through the public feedback API. Hosting approval must cover both transfer of the artifact to Vercel and intended audience/public redistribution. Deployment protection can restrict a preview audience but is not a dataset license. Do not enable auto Git deployment until its data-input path is explicit.

## Reproducible local preparation (no provider operations)

From repository root in PowerShell:

```powershell
npm ci
npm run data:inspect
npm run data:prepare
$env:INSIGHTFLOW_DATA_MODE='official'
npm run check
npm run package:verify
```

The source must be the original `data/raw/customer_feedback.csv`, SHA-256 `82b09450e0e5144c4a21cb33a9556dab6afd7618228496e7f4c321f687250c41`. Exact assertions cover 7,000 rows, 320 hashes, 6,680 repeats, all raw/distinct category counts, top-20 total 5,025, zero rejects and no complaint dates. Generation time varies; data and grouping are deterministic. The verification report binds the exact generated bytes by artifact SHA-256.

Build readiness validates the full JSON, hashes, verbatim annotation evidence and dataset assertions, rather than checking file existence. It also binds the original ordered `(rowNumber, rawText, category)` content to fingerprint `6416408f949678e72e3d9a530d311f11725171bb77e484595aa82b5168cf82e5`, independently checked against the checksum-verified CSV. Merely copying source checksum metadata cannot legitimize altered or renumbered records. `VERCEL` builds require explicit data mode. Production runtime also requires explicit mode; official mode with absent/corrupt JSON returns 503, never fixture fallback. Explicit `fixture` mode remains supported and labeled for development/demos; it is not an official release.

`package:verify` checks seven domain API traces, copies standalone + static/public into an isolated ignored release directory, removes symlink dependence, checks no `.env` or raw CSV is included, verifies artifact-byte identity, then launches **that relocated package** with an environment that contains no developer/provider credentials. It retrieves all 7,000 records and all 320 patterns through paginated HTTP, checks full invariants, 401 writes, 503 missing-artifact behavior and 503 unset-mode behavior. It stops its server. Local report: `artifacts/production-packages/verification.json`; packages remain ignored for review. This proves the locally built runtime package, not remote Vercel packaging or Auth.

## Only after hosting/data-transfer authorization

Vercel currently caps function request/response payloads at 4.5 MB, independently of the backend's frozen 5 MiB CSV ceiling. Use a conservative 4 MiB upload UI limit on Vercel (including multipart allowance); platform-level 413 responses may not have the application's JSON envelope. The official original is only 660,099 bytes. The 5.7 MB JSON is bundled server input, not an HTTP upload or unpaginated response. Actual function bundles must also be checked against the target's bundle limit; a standalone package is not equivalent to each Vercel function. Very large private-batch issue-evidence responses may need coordinated pagination before that scale is enabled. [Current Vercel limits](https://vercel.com/docs/functions/limitations).

1. Choose/link a Vercel project from this root; framework Next.js, build `npm run build`, Node 24 (local verified version), default framework output settings. Do not override output directory to `.next/standalone`. Inspect CLI upload inputs against `.vercelignore` before authorizing the upload.
2. In Preview and Production settings set `INSIGHTFLOW_DATA_MODE=official`, `INSIGHTFLOW_WRITES_ENABLED=false` initially, and `APP_ORIGIN` to each exact environment's chosen origin. Supply Supabase URL/publishable key only when configured. Never add service-role/Adaption secrets to public variables. Adaption is a separate local controlled workflow and does not need a Vercel API key.
3. Run `vercel deploy` from the prepared root only under separate remote authorization. For an authorized production promotion use the selected project's documented CLI flow after preview verification. No CLI is installed or remote call performed here.
4. Set `SMOKE_BASE_URL` to the approved preview and run `npm run smoke`; inspect all six screens. `smoke:integration` includes unauthenticated write-denial attempts and local browser mocks; use a disposable read-only preview for that full suite. Check real 7,000/320/6,680 values, `official_csv` provenance, max occurrence 295, top20 5,025, CSV, unknown sentiment 218, no fabricated provider results and no missing artifact 503. Record URL/commit/build ID and real results before declaring deployed.
5. If build input is absent, fix preparation/inclusion and rebuild. Do not select fixtures to make the official release pass. If deployment fails, retain logs privately, restore the previous verified deployment, keep writes disabled and investigate config/artifact differences. Environment changes require redeployment; do not assume cached builds adopt runtime secrets correctly.
