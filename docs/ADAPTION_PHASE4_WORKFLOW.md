## Product use: training-data curation with independent evaluation

Adaptive Data creates optimized instruction training data. The 25-pattern pilot asks for structured review-analysis completions with exact source evidence. Those completions are **candidate training targets**, not independent sentiment truth or online predictions. Missing completion generation is supported by prompt/context mapping. Rephrasing, reasoning traces, deduplication and language expansion are disabled to preserve exact correspondence. Review context includes source category/frequency but the prompt explicitly forbids repetition-based severity/customer inference. The pilot is stratified for category, negation and mixed clauses, not a random held-out benchmark.

The implemented downstream workflow consumes a real normalized run artifact, validates all 25 source hashes/evidence and generates a paired sentiment/severity/topic agreement report against **independently authored human gold**, plus a completion-review sheet. It exports instruction training examples only after a named human approves each exact candidate completion hash. Each exported row retains verbatim source context, original hash, review identity/time and real run provenance. This is an auditable local data workflow (`adaption:curate`), not a claim that a classifier was trained or integrated into dashboard metrics.

Gold must be filled before seeing provider output where practical. Fill `gold_sentiment`, `gold_severity`, `gold_issue_types` (JSON string array, `[]` when none), and `review_status=verified`; preserve exact hash/review and record reviewer/process in notes. Do not copy heuristics/provider answers into gold. Curation evaluates candidate and heuristic on the same accepted, verified pilot patterns; denominators and missing rows are explicit. With blank gold, all accuracy values are null. Topic score is exact topic-set agreement, not fuzzy taxonomy quality. Provider dataset grades are separate and are never called classification accuracy.

## Separately gated commands (not executed in this phase)

Approval flags are local accident prevention, **not authorization granted by this document**. Obtain human authorization for each operation first. Commands default to no network even when credentials exist. The shown capitalized values are placeholders, never actual IDs or quotes.

1. **Upload/preprocessing**: `npm run adaption:upload -- --allow-network --approve-transfer PILOT_SHA256`. `upload_file(...,processing_mode='adapt')` creates/uploads/completes the reviewed file for preprocessing; it does not call `datasets.adapt`. The upload helper's transport can contact provider-controlled object storage. Account transfer/retention and any ingestion charge terms need review before upload; no zero-cost ingestion guarantee is inferred. Records real dataset ID/status in `upload.json`. Ingestion is asynchronous; it must reach `awaiting_input` with exactly 25 rows before an estimate/run. No unattended poll or adaptation is initiated.
2. **Quote only**: `npm run adaption:estimate -- --dataset-id ACTUAL_DATASET_ID --allow-network --approve-estimate CONFIG_SHA256`. Requires the recorded upload with matching hashes; preflight confirms exact row count/awaiting_input. Calls `datasets.adapt(...,estimate=True)` and requires no run ID and finite nonnegative credits. Writes `estimate.json`. Review this actual quote and compute its file SHA-256 locally before asking for spend approval. No quote exists in this phase.
3. **One paid submission**: `npm run adaption:execute -- --allow-network --approve-spend ESTIMATE_FILE_SHA256 --max-credits APPROVED_CREDITS`. Requires matching dataset/input/config, estimate-only quote no older than 24h, finite approved cap >= quote, and awaiting_input. Uses exactly the quoted config, `estimate=False`, retries disabled, writes actual returned run ID and submitted status. **The SDK has no inspected hard billing-cap argument**: max-credits is a preflight check against the quote, not an enforceable provider billing limit. Confirm provider pricing/quote guarantees before approval. Actual cost remains null because inspected adapt/status responses expose estimates/status, not billing usage. Obtain actual usage separately if available, with original provider evidence; never copy estimate into actual.
4. **Read/download only**: `npm run adaption:download -- --allow-network --approve-run ACTUAL_RUN_ID`. Records current status without polling; requires success and `datasets.get` matching the recorded run. Downloads JSONL as actual bytes via SDK `.read()`, bounded to 10 MiB after receipt, into ignored `provider-output.jsonl`. Partial/failed/changed output is refused. If the provider clears run_id on completion, this strict command will refuse rather than guess; inspect real run provenance and review a mapping/recovery change. It never relaunches adaptation. Status observation time is not a provider-reported completion time.

Upload/quote/execution/download each exclusively creates `*.attempt.json` before submission. Successful responses are atomically recorded; timeouts/unexpected responses retain `unknown_requires_reconciliation`. Existing attempts block repeats before provider client creation; concurrent duplicates also fail exclusive reservation. No automatic retry or force/reset flag exists. A reservation without a run ID does not prove nothing was charged. Inspect the account/audit logs privately and reconcile before any authorized recovery; do not simply delete locks. Stale quote renewal likewise needs deliberate reconciliation/new approved attempt, not silent overwrite. Preparation cannot erase this trail. Provider errors are sanitized, not printed with credentials/content.

## Explicit offline output mapping and validation

The actual export columns/nesting must be inspected after an authorized run. A mapper is deliberately specified rather than guessing fields before real data exists:

- Select the real original source-pattern hash column (or recover hash only from a byte-identical original review matching manifest). Never map by row position or regenerated/rephrased review.
- Parse the real generated completion JSON; map **only** its supported sentiment/severity/topic/aspect/evidence fields to canonical Annotation. Preserve `reviewStatus='unreviewed'`, `confidence=null`, `analyzedBy='adaption'`, actual pipeline/mapper version. Fail on markdown/prose/unknown structures until reviewed parsing rules exist.
- Keep original export bytes/checksum and an auditable mapping record with actual dataset/run IDs, export SHA, normalized artifact SHA and mapper version. RunProvenance requires actual IDs, source/config/normalized-artifact hashes, actual/observed completion timestamp with documented origin, and actualCredits or null. Never use a test fixture or guessed ID as evidence of a real run.
- Run `npm run adaption:validate -- --input NORMALIZED_JSONL --provenance REAL_PROVENANCE_JSON`. It uses the default local manifest/gold paths; custom paths can be supplied. Complete schema/hash/negation/evidence checks must pass. The validator also uses the paired sentiment/severity/topic evaluator; verified gold must contain all three labels and exact source text. Duplicate/out-of-pilot/altered gold is rejected rather than inflating a metric denominator. A schema pass does not establish human truth.
- Run `npm run adaption:curate -- NORMALIZED_JSONL MANIFEST_JSON REAL_PROVENANCE_JSON HUMAN_REVIEW_CSV`. This writes paired evaluation, empty approved-training output and an unreviewed completion-review JSON template next to the input. Review entire completions, including aspect truth and denied allegations; fill only approved entries with status verified, real reviewer/time and unchanged candidate hash. Remove rejected/pending entries from a separate approvals JSON. Then rerun with `APPROVALS_JSON` as the fifth argument. Stale/unknown/duplicate approvals fail. The exported `.training.jsonl` contains only human-approved instruction examples, with full provenance. Curation never overwrites the original completion-review template or gold.

No provider export exists here; real-column mapping remains an explicit post-download inspection gate. Unit tests use clearly labeled authored candidates/provider doubles and demonstrate rejection/evaluation/approval logic without claiming a real result. Fine-tuning/evaluating a downstream classifier requires separately approved work, a held-out review set and actual inference metrics before replacing heuristics. No additional classifier/API spend is hidden in curation.
